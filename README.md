# internship-to-resume

一个面向不同岗位和行业的实习简历 Skill。即使手中主要是项目方案、代码或周报，也会先推演与实习岗位相称的业务切入点，生成具体的候选简历；确认个人分工后形成可投递稿。也能根据招聘 JD 生成岗位定制版本。

适合研发、产品、运营、数据分析、设计、测试、项目交付和职能支持等经历。不需要先准备完整项目故事，也不要求提供源码；只有零散笔记或口述也可以开始。

## 工作方式

1. 从材料中还原服务对象、业务问题和项目工作链路。
2. 找到实习生可能实际参与、可通过记录复原的切入点，先写具体候选条目。
3. 对个人归属不明的条目标「可选·待确认」，附材料出处及需要核实的动作。
4. 根据用户选择形成可投递稿，再补有依据的交付结果或量化指标。
5. 按需提供 JD 定制稿和面试提纲。

同一份经历可以按不同求职方向选择重点，但不会改变实际责任。候选稿可以推演，正式稿只写确认过的个人动作；能够复述项目原理或事后复现，不等于曾负责该项目。没有效果数字时，仍可用具体工作范围和交付结果表达贡献。

## 使用

将整个技能目录放入所用工具支持的技能目录，保持 `SKILL.md` 与 `references/` 的相对位置。支持命名调用的环境中可以使用：

```text
请用 $internship-to-resume 完善我的实习经历。
目标岗位：产品实习生。
我会提供项目介绍、工作笔记和已有简历。
请先给具体候选简历条目，把个人归属不明的部分标为「可选·待确认」，再补问关键细节。
数字需要有来源；不确定的内容放在待确认清单。
```

也可以直接从口述开始：

```text
请用 $internship-to-resume。
我实习时主要整理周报、核对数据，也帮同事准备过汇报。
请帮我找到值得写的贡献，不要一开始让我填写完整问卷。
```

只提供与任务相关、可以使用的材料；不需要上传账号、密钥或无关个人信息。技能会使用宿主环境现有的读取能力，某种文件不能读取时会说明缺口。

只有项目资料时也可以直接调用。Skill 会把「材料证明项目做了什么」「可能适合实习生承担什么」「你实际做过什么」分开，给每条候选附简短追溯卡。使用者选择做过、部分做过或没做过的条目后，再形成可投递稿。

## 按 JD 定制简历

提供基础简历和招聘 JD 后，Skill 会自动拆解岗位要求、映射已有经历、调整顺序与表达，交付岗位稿、对齐说明、修改摘要和关键缺口。保留基础简历，方便下一次定制。

```text
请用 $internship-to-resume，把我的基础简历改成适合这份 JD 的版本。
突出相关经历，保留真实职责和数据，不新增我没有的技能。
先给可用的简历稿，再说明改动和关键缺口。
基础简历：见附件。
目标 JD：以下粘贴招聘原文。
```

一份基础简历也可以对应多个岗位：

```text
请用 $internship-to-resume，分别对齐下面三份 JD。
每个岗位给我一份独立简历和简短对齐说明，保留基础稿。
共用的信息只问一次；某个岗位的缺口不要影响其他版本。
```

已有简历与 JD 时无需先填写统一问卷。没有明确证据的要求会列为待确认或缺口；经历事实、学历、任职时间和数字不会因岗位而改变。匹配说明使用可解释的对应关系，不宣称可预测招聘系统通过率。

这里的自动化是收到简历与 JD 后直接完成定制，不包含定时抓取招聘、自动投递或向他人发送简历。跨聊天使用时需要在新任务中提供基础稿或可访问的材料。

## 文件结构

```text
internship-to-resume/
  SKILL.md
  README.md
  agents/openai.yaml
  references/evidence.md
  references/metrics.md
  references/scenarios.md
  references/jd-alignment.md
```

`SKILL.md` 选择经历提炼或 JD 定制流程，参考文件分别处理材料归属、量化指标、场景访谈和岗位定制。`agents/openai.yaml` 提供支持该格式的工具使用的界面元数据。

## 公开内容边界

技能包仅包含通用方法和虚构教学示例，不包含真实公司、客户、源代码、简历、工作记录或本地机器路径。使用者材料及生成的个人分析应留在各自任务中，不提交到技能仓库。
